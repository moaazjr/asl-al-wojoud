# Project: أصل الوجود (Asl Al-Wujud) — Arabic RTL docs site

## Commands
- `npm run dev` — dev server
- `npm run build` — production build (Turbopack)
- `npm run start` — serve production build
- `npm run lint` — ESLint (React 19 hook rules are strict; avoid `setState` inside `useEffect`)
- `npm run typecheck` — `tsc --noEmit`
- `npm run parse` — regenerate book content from `source/*.docx` into `data/generated/`
- `npm run db:migrate` — create + apply a Prisma migration (`prisma migrate dev`)
- `npm run db:seed` — seed the admin user (`prisma db seed`)
- `npm run db:push` — push schema to DB without migration history (`prisma db push`)
- First-time DB setup: `docker compose up -d` → `npm run db:migrate` → `npm run db:seed`

## Architecture
- Content source: `source/` (Arabic DOCX + HTML TOC). Run `npm run parse` to regenerate `data/generated/{toc.json, book-1..7.json, index.json}`.
- 686 sections across 7 chapters. Routes: `/` (landing), `/[bab]` (chapter), `/[bab]/[section]` (reader), `/index` (full TOC).
- RTL Arabic (`dir="rtl" lang="ar"`), manuscript theme (paper/ink/gold), Amiri/Reem Kufi/Noto Naskh fonts.
- Dark/light via `next-themes` (class strategy).
- **Full-text search** (Phase 2): FlexSearch with custom Arabic encoder; `public/search-docs.json` generated by `npm run parse`; Ctrl+K command palette (`features/search/`).
- **Auth + discussions** (Phase 3): Client-side repository pattern — see `interfaces/` (contracts), `services/` (business logic + permissions), `repositories/` (LocalStorage adapters). UI never touches `localStorage` directly; it goes through React contexts (`features/auth`, `features/notifications`) → services → repositories. Text selection in a section opens a popover (Highlight / Comment → discussion thread). Two roles: `user` (create/like/edit-own), `admin` (reply/resolve/reopen/pin/delete-any + dashboard at `/dashboard`). Seeded admin: `admin@asl-alwujud.local` / `admin123`. Notifications fire on admin reply/resolve/reopen. Swap the LocalStorage adapters for Supabase/Firebase/REST/GraphQL by implementing the same interfaces — no UI changes.
- **PostgreSQL backend** (Phase 4): `NEXT_PUBLIC_DATA_BACKEND=prisma` switches the container (`services/container.ts`) from LocalStorage adapters to REST adapters (`repositories/rest/`) that call Next.js API routes (`app/api/**`). The API routes use Prisma 7 + `@prisma/adapter-pg` + cookie sessions (`lib/server-auth.ts`). Server-side permission checks reuse the same `services/permissions.ts` as the client (defense-in-depth). Identity is derived from the session cookie server-side — client-sent user IDs are ignored. Password hashing: scrypt (`lib/server-auth.ts`). Prisma 7 notes: `schema.prisma` datasource has no `url` (it lives in `prisma.config.ts`); `PrismaClient` requires a driver adapter. The REST notification adapter's `create` is a no-op — API routes create notifications server-side after admin reply/resolve/reopen.
- Old server-side comment system (API routes + Vercel KV) was **removed**. `@vercel/kv` is no longer used.

## Code style
- DO NOT add comments unless explicitly requested.
- Server Components by default; mark interactive islands with `"use client"`.
- Content loader is server-only (`lib/content.ts` reads generated JSON via `fs`).
